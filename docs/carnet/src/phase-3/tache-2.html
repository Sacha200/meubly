Tâche 2 : le socle de collecte

Trois petits outils sur lesquels reposent tous les adaptateurs marchands : reconnaître un code EAN, normaliser un texte pour comparer des marques, et télécharger une page en respectant le marchand.

PR #27 mergée feat/ingestion-core commit b6b14df 25 nov. 2026

Objectif

Les tâches suivantes (adaptateurs Shopify et Nordic Nest) vont lire des milliers de fiches produit chez Connox, Fleux et Nordic Nest. Avant d'écrire la moindre ligne propre à un marchand, on pose trois briques communes :

  • Identifier un produit sans ambiguïté. Le même article porte le même EAN (le code-barres) chez tous les marchands. C'est la clé du rapprochement, encore faut-il ne garder que de vrais EAN.
  • Comparer des marques écrites différemment. « &Tradition », « &tradition » et « Tradition » doivent donner la même chose.
  • Rester un visiteur correct. Le robot se présente sous son vrai nom, lit robots.txt, ne va pas plus vite qu'une page toutes les 2 secondes par site, et s'arrête net s'il est refusé. Aucun contournement.

Étapes

Méthode TDD : on écrit les tests, on les regarde échouer, puis on écrit le code qui les fait passer.

gtin.js

meubly-back/ingestion/gtin.js

Un EAN n'est pas n'importe quelle suite de chiffres : son dernier chiffre est une clé de contrôle calculée à partir des autres. Vérifier cette clé élimine les références fabricant, les fautes de saisie et les numéros internes que certains marchands rangent dans les mêmes champs.

{{code:meubly-back/ingestion/gtin.js}}
  • /^(\d{8}|\d{12,14})$/Accepte 8, 12, 13 ou 14 chiffres, rien d'autre (pas de lettre, pas de tiret). Ce sont les longueurs EAN-8, UPC-12, EAN-13 et GTIN-14.
  • digits.pop()Retire le dernier chiffre : c'est la clé qu'on va recalculer et comparer.
  • reverse() + poids 3/1En partant de la droite, on multiplie les chiffres alternativement par 3 et par 1, puis on additionne. Partir de la droite permet d'utiliser la même règle pour toutes les longueurs.
  • (10 - sum % 10) % 10La clé est ce qu'il faut ajouter pour arriver à la dizaine suivante. Le second % 10 donne 0 quand la somme tombe déjà juste.
  • pickGtin(...candidates)Les marchands Shopify rangent l'EAN tantôt dans barcode, tantôt dans sku (Fleux). On essaie chaque champ, nettoyé par String(x ?? "").trim(), et on garde le premier valide, sinon null.

text.js

meubly-back/ingestion/text.js

Sert à comparer deux marques ou deux titres sans être gêné par la casse, les accents ou la ponctuation.

{{code:meubly-back/ingestion/text.js}}
  • normalize("NFD")Décompose chaque lettre accentuée en lettre + accent séparé : « é » devient « e » suivi d'un accent aigu.
  • [̀-ͯ]Cette plage Unicode contient les accents isolés. On les supprime, il ne reste que la lettre.
  • replace(/&/g, "")Le « & » est retiré sans laisser d'espace : « &Tradition » devient « tradition ».
  • [^a-z0-9]+ → " "Toute suite de caractères qui n'est ni lettre ni chiffre devient un seul espace, grâce au +. « Fritz Hansen » et « Fritz - Hansen » donnent tous deux « fritz hansen ».
  • trim()Enlève l'espace éventuel laissé au début ou à la fin.

politeFetch.js

meubly-back/ingestion/politeFetch.js

Le module le plus important. createPoliteFetch fabrique une fonction get(url) qui applique toutes les règles de politesse. Toute la collecte passera par elle : aucun adaptateur n'appelle fetch directement.

{{code:meubly-back/ingestion/politeFetch.js}}
  • BlockedError / HttpErrorDeux types d'erreur distincts. BlockedError veut dire « le marchand ne veut pas de nous » : la collecte de ce marchand s'arrête. HttpError est une panne ordinaire, qui porte le code status.
  • parseRobotsLit robots.txt ligne par ligne. Plusieurs lignes User-agent qui se suivent forment un seul groupe. Si un groupe vise prixolibot, lui seul s'applique, sinon c'est le groupe *.
  • toRegexTraduit un motif robots.txt en expression régulière : * = n'importe quoi, $ final = fin d'URL. Les autres caractères spéciaux sont échappés.
  • isAllowedParmi les règles qui correspondent, la plus longue (donc la plus précise) l'emporte. À longueur égale, Allow gagne. Sans règle correspondante, tout est autorisé.
  • Paramètres par défautfetchImpl et sleep sont injectables : les tests passent de faux réseaux et de fausses attentes, sinon chaque test durerait des minutes.
  • requestAvant chaque requête vers un hôte déjà visité, on attend delayMs (2 s). Le premier appel à un hôte part tout de suite.
  • requestWithRetrySur un 429 (« trop de requêtes »), on attend 60 s et on réessaie, 3 fois au plus. Le dernier 429 est renvoyé tel quel et finira en HttpError.
  • robotsRulesrobots.txt est lu une seule fois par site, puis gardé dans une Map. S'il est absent (404), la liste de règles est vide : tout est autorisé.
  • politeFetch(url)Ordre des contrôles : robots.txt d'abord (sans jamais appeler la page interdite), puis la requête, puis le refus (403, ou page courte contenant captcha, datadome ou cf-chl), puis tout autre statut non 2xx.
  • body.length < 20_000Une vraie fiche produit peut citer « captcha » dans un script. Une page de défi, elle, est courte. La limite évite les fausses alertes.

Corrections

Corrigé dans la PR #28

Après le merge de la PR #27, une relecture complète des tests a trouvé des écarts avec le code donné. Le code affiché sur cette page est la version corrigée.

  • Test sans effet. not.toHaveBeenNthCalledWith(forbidden, ...) attend un numéro d'appel en premier argument : avec une URL, il ne trouve aucun appel et le .not réussit toujours, même si la page interdite est téléchargée. Remplacé par not.toHaveBeenCalledWith.
  • Nom inversé. « autorise une URL interdite... » est devenu « refuse une URL interdite... ».
  • Test manquant. « autorise tout quand robots.txt est absent (404) » ajouté, comme le demande le plan.
  • Coquilles. « polices », « est GTIN », « minuscule », et la ligne vide entre les blocs /** */ et leur fonction, qui empêchait l'éditeur d'afficher la documentation au survol.

La leçon : relire tous les fichiers tapés, tests compris, avant le commit. Un test vert ne prouve pas qu'il vérifie quelque chose.

À retenir

  • Injection de dépendances. Passer fetchImpl et sleep en paramètres rend le code testable sans réseau ni attente réelle. On réutilisera ce schéma dans les adaptateurs.
  • Un refus est définitif. BlockedError n'est jamais rattrapé pour réessayer autrement. C'est la règle du projet : on ne contourne pas un marchand qui bloque.
  • Hors périmètre : la directive Crawl-delay de robots.txt est ignorée, remplacée par le délai fixe de 2 s. Les cas exotiques de robots.txt (encodage d'URL, groupes mal formés) ne sont pas gérés.
  • Suite : tâche 3, l'adaptateur Shopify (Connox et Fleux), qui utilisera createPoliteFetch et pickGtin.
