Tâche 4 : rapprochement et écriture en base

Décider, pour chaque article lu chez un marchand, s'il rejoint un meuble déjà connu, en crée un nouveau ou attend l'avis d'un admin, puis l'écrire en base avec son offre.

4a en cours feat/ingestion-matching 26 nov. 2026

Objectif

L'adaptateur de la tâche 3 rend des articles au format commun. Il reste à les relier au catalogue : c'est ce qui permet d'afficher plusieurs marchands sur une même fiche. La règle de la spec (6.4) est simple : l'EAN décide. Sans EAN, on ne crée jamais de meuble automatiquement, on propose au mieux un rapprochement à valider.

brands.js

meubly-back/ingestion/brands.js

On ne collecte que les marques vendues par au moins deux marchands : un produit vendu par un seul marchand n'a rien à comparer.

// Marques comparables d'un marchand a l'autre : meme nom une fois normalise et ramene a son alias.
import { normText } from "./text.js";

/** Ecarts de nom releves entre Connox, Fleux et Nordic Nest (tache 0). */
export const BRAND_ALIASES = {
  "audo copenhagen": "audo",
  "and tradition": "tradition",
  fermliving: "ferm living",
  "hay denmark": "hay",
};

/**
 * Nom de marque canonique : normalise, sans "The " initial, alias applique.
 * @param {string} name
 * @returns {string}
 */
export function canonicalBrand(name) {
  const brand = normText(name).replace(/^the /, "");
  return BRAND_ALIASES[brand] ?? brand;
}

/**
 * Marques presentes chez au moins deux marchands.
 * @param {Set<string>[]} sets  marques de chaque marchand
 * @returns {Set<string>}  noms canoniques
 */
export function commonBrands(sets) {
  const counts = new Map();
  for (const set of sets) {
    for (const brand of new Set([...set].map(canonicalBrand))) {
      counts.set(brand, (counts.get(brand) ?? 0) + 1);
    }
  }
  return new Set([...counts].filter(([, count]) => count >= 2).map(([brand]) => brand));
}
  • BRAND_ALIASESLes écarts de nom relevés à la tâche 0 : « Audo Copenhagen » chez l'un, « Audo » chez l'autre. normText a déjà transformé « & » en « and ».
  • new Set intérieurSi un marchand liste « audo » et « audo copenhagen », les deux donnent « audo » : la marque ne compte qu'une fois pour ce marchand.
  • noms canoniquescommonBrands rend des noms canoniques. L'adaptateur filtre sur ses propres noms : run.js (4b) devra lui passer les noms d'origine dont la forme canonique est commune.

categoryMap.js

meubly-back/ingestion/categoryMap.js

Un meuble créé doit être rangé dans l'une des 11 catégories racines créées à la tâche 1. On regarde le type annoncé par le marchand, puis le titre.

// Range un article dans l'une des 11 categories racines du catalogue maison (migration de la tache 1).
import { normText } from "./text.js";

/**
 * La premiere regle qui correspond l'emporte : l'ordre compte (le jardin prime sur la table).
 * Connox annonce ses types en allemand (Leuchten, Geschirr, Kinder) : ils sont dans la table.
 */
const RULES = [
  ["Jardin et exterieur", /jardin|exterieur|outdoor|terrasse|parasol|transat/],
  ["Luminaires", /lampe|suspension|lampadaire|applique|baladeuse|luminaire|plafonnier|leuchten/],
  ["Enfant", /enfant|bebe|baby|kids|kinder/],
  ["Salle de bain", /salle de bain|douche|porte savon|serviette de bain/],
  [
    "Cuisine et salle a manger",
    /cuisine|kuche|kochen|geschirr|arts de la table|salle a manger|sets? de table|vaisselle|assiette|tasse|mug|carafe|pichet|sucrier|\bbol\b|plateau|dessous de verre|couverts|casserole|theiere|cafetiere/,
  ],
  ["Bureau", /bureau/],
  ["Chambre", /\blit\b(?! de jour)|matelas|chevet|linge de lit|housse de couette|oreiller/],
  [
    "Rangement",
    /etagere|bibliotheque|commode|buffet|rangement|armoire|console|portemanteau|patere/,
  ],
  ["Decoration", /vase|miroir|tapis|coussin|bougeoir|bougie|plaid|cadre|affiche|horloge/],
  [
    "Salon",
    /chaise|tabouret|fauteuil|lounge|pouf|canape|sofa|daybed|banquette|lit de jour|\bbanc\b|\btable\b/,
  ],
];

const labelOf = (text) => RULES.find(([, pattern]) => pattern.test(normText(text ?? "")))?.[0];

/**
 * Categorie racine d'un article : d'apres le type annonce par le marchand, sinon le titre.
 * @param {{ categoryHint: string|null, productTitle: string }} item
 * @returns {string}
 */
export function categoryLabelFor(item) {
  return labelOf(item.categoryHint) ?? labelOf(item.productTitle) ?? "Autres";
}
  • l'ordre comptefind s'arrête à la première règle qui correspond : « Table de jardin » finit en Jardin, pas en Salon.
  • \bLimite de mot. Sans elle, « cartable » contenait « table » et partait en Salon, « blanc » contenait « banc ».
  • (?! de jour)« Mais pas suivi de " de jour " » : un lit de jour est un canapé, il va dans Salon.
  • types allemandsConnox annonce ses types en allemand (Leuchten, Geschirr, Küche & Kochen, Kinder). normText retire les accents : « Küche » devient « kuche ».
  • approximatifSur les catalogues du spike, « Autres » regroupe 17 % des produits Connox et 53 % des produits Fleux (chaussettes, affiches, jeux). Ces catégories servent à la navigation, on pourra les affiner.

match.js

meubly-back/ingestion/match.js

La décision ne touche pas la base elle-même : elle reçoit deux fonctions de recherche (lookup). En 4b, ce seront celles d'ingestionRepository ; dans les tests, des fonctions factices.

// Rapprochement d'un article marchand avec le catalogue (spec 6.4) : l'EAN decide, sinon un admin.
import { isGtin } from "./gtin.js";

/**
 * @param {import("./adapters/index.js").ScrapedItem} item
 * @param {{
 *   furnitureByGtin: (gtin: string) => Promise<{ furniture_id: string, product_id: string|null }|null>,
 *   similar: (brand: string, title: string) => Promise<{ furniture_id: string, score: number }[]>,
 * }} lookup
 * @returns {Promise<{ action: "attach", furnitureId: string } | { action: "create" }
 *   | { action: "candidate", candidates: { furniture_id: string, score: number }[] } | { action: "skip" }>}
 */
export async function decide(item, { furnitureByGtin, similar }) {
  if (isGtin(item.gtin)) {
    const known = await furnitureByGtin(item.gtin);
    return known ? { action: "attach", furnitureId: known.furniture_id } : { action: "create" };
  }
  const candidates = await similar(item.brand, item.productTitle);
  return candidates.length ? { action: "candidate", candidates } : { action: "skip" };
}
  • attachEAN connu : l'article devient une offre de plus sur le meuble existant.
  • createEAN valide inconnu : nouveau meuble.
  • candidateSans EAN mais un meuble proche de même marque : un admin tranchera.
  • skipSans EAN ni meuble proche : l'article est gardé dans partner_product, sans meuble.
  • isGtin revérifiéL'adaptateur a déjà contrôlé l'EAN, mais decide est la frontière avec la base : un futur adaptateur moins rigoureux ne pourra pas créer de meuble avec un faux EAN.

import { describe, it, expect, vi } from "vitest";
import { decide } from "../../../ingestion/match.js";

const EAN = "5710441309116";
const item = (gtin) => ({ gtin, brand: "HAY", productTitle: "Pouf Planar" });

function lookup({ known = null, similar = [] } = {}) {
  return {
    furnitureByGtin: vi.fn(async () => known),
    similar: vi.fn(async () => similar),
  };
}

describe("decide", () => {
  it("rattache a un meuble deja connu par son EAN", async () => {
    const l = lookup({ known: { furniture_id: "f1", product_id: "p1" } });
    expect(await decide(item(EAN), l)).toEqual({ action: "attach", furnitureId: "f1" });
    expect(l.similar).not.toHaveBeenCalled();
  });

  it("cree un meuble pour un EAN valide inconnu", async () => {
    const l = lookup();
    expect(await decide(item(EAN), l)).toEqual({ action: "create" });
    expect(l.similar).not.toHaveBeenCalled();
  });

  it("propose un rapprochement sans EAN quand un meuble proche existe", async () => {
    const candidates = [{ furniture_id: "f2", score: 0.8 }];
    const l = lookup({ similar: candidates });
    expect(await decide(item(null), l)).toEqual({ action: "candidate", candidates });
    expect(l.similar).toHaveBeenCalledWith("HAY", "Pouf Planar");
  });

  it("ignore un article sans EAN ni meuble proche", async () => {
    expect(await decide(item(null), lookup())).toEqual({ action: "skip" });
  });

  it("traite un EAN a cle fausse comme une absence d'EAN", async () => {
    const l = lookup();
    expect(await decide(item("5710441309117"), l)).toEqual({ action: "skip" });
    expect(l.furnitureByGtin).not.toHaveBeenCalled();
  });
});
  • it.eachUn même test répété sur un tableau de cas ; %s place chaque valeur dans le nom du test.
  • vi.fnFonction espion : elle enregistre ses appels. toHaveBeenCalledWith vérifie les arguments ; toHaveBeenCalled, lui, n'en regarde aucun.
  • clé fausse5710441309117 au lieu de …116 : traité comme une absence d'EAN, et la base n'est même pas interrogée.
